这里列举了一些常见的前端面试问题

css 和盒子模型（box-sizing）​

  • 标准盒子模型（content-box）： margin + border + padding + content
  • IE 盒子模型（border-box）： margin + content(这个 content 就是上面盒子模型的后面三个) 所以设置盒子的 width 和 height 属性是，不同的盒子模型有不同的计算结果，如果设置高度和宽度都为 200px，标准盒子模型会设置 content 的宽高为 200px，IE 盒子模型则是设置 border，padding 和 content 的宽高和为 200px，所以在视觉上标准盒子会比 IE 盒子大

css 选择器的优先级​

  • 在写 css 样式的时候，会给同一个元素添加多个样式，此时可能会发生样式冲突，发生冲突后，那个选择器的优先级高就显示该选择器的样式。

  • !important > 行内样式 > id > 类、伪类、属性 > 标签

隐藏元素的方法​

  • display:none（元素从文档流中消失，不占据页面空间）
  • opacity: 0 （元素只是不可见，依旧占据页面空间，可以相应事件）
  • visibility: hidden
  • position: absolute （将元素定位到视口外面）
  • clip-path（将元素剪切掉）

px 和 rem 的区别​

  • px 是绝对单位长度，是显示器给我们呈现画面的像素
  • rem 是相对单位，它是相对于 html 根节点的 font-size 的值，默认是 1rem = 16px

重绘和重排有什么区别​

  • 重排（回流）： 布局引擎会根据所有的样式计算出盒模型在页面上的位置和大小
  • 重绘：计算好盒模型的位置、大小和其他的一些属性之后， 浏览器会根据盒模型的特性进行绘制
  • 对 DOM 的大小、位置等样式的读取或者修改，浏览器需要重新计算元素的这些几何属性，这就叫做重排
  • 对 DOM 的一些不影响布局的样式进行修改，比如 color，浏览器不需要重新计算 DOM 的几何属性，只需要重新绘制该元素的新样式，这里就只出发了重绘
  • 重排一定触发重绘，重绘不一定出发重排

让一个元素水平垂直居中的方法​

  • 定位+margin --> 子元素 absolute， margin 为 auto，left，right 这些都为 0
  • 定位+transform --> 子元素 absolute，left: 50%, top: 50%, transform: translate(-50%, -50%)
  • flex 布局
  • grid 布局
  • table 布局

说一下闭包， 闭包有什么特点​

  • 什么是闭包？函数嵌套函数，内部函数被外部函数返回并保存下来时，就会产生闭包
  • 特点：可以重复利用变量，并且这个变量不会污染全局的一种机制，这个变量一直保存在内存中，不会被垃圾回收机制回收
  • 缺点：闭包较多的时候，会消耗内存，导致页面的性能下降，在 IE 浏览器中才会导致内存泄漏 使用场景： 防抖，节流，函数嵌套函数避免全局污染的时候

前端的内存泄漏怎么理解？​

  • js 里已经分配内存地址的对象，但是由于长时间没有释放或者没办法清楚，造成长期占用内存的现象，会让内存资源大幅浪费，最终导致运行速度慢，甚至崩溃的情况。
  • 原因： 一些未清空的定时器，过度的闭包，一些引用元素没有被清除

事件委托​

  • 也叫做事件代理，原理就是利用了事件冒泡机制，把子元素的事件绑定到了父元素的身上，如果子元素阻止了事件冒泡，那么委托也就不成立了（使用 event.stopPropagation()）来阻止事件冒泡。
  • addEventListener('click', funciton, true/false) 默认是 false（事件冒泡）， ture（事件捕获）
  • 好处：提高性能，减少事件的绑定，也就减少了内存的占用

基本数据类型和引用数据类型​

  • 基本数据类型：String Number Boolean undefined null 基本数据类型保存在栈内存中，保存的就是一个具体的值
  • 引用数据类型： Object Function Array 保存在堆内存中，生命一个引用类型的变量，它保存的事引用类型数据的地址 假如生命两个引用类型的变量同时指向了一个地址的时候，修改其中一个那么另外一个也会改变

说一下原型链​

原型就是一个普通对象，它是为构造函数的实例共享属性和方法；所有实例中引用的原型都是同一个对象，使用 prototype 可以把方法挂在原型上，内存只保存一份。proto可以理解为指针，实例对象中的属性，指向了构造函数的原型（prototype）

new 操作符具体做了什么​

    funciton newFun(Fun, ...args) {
        // 1. 先创建一个空对象
        const newObj = {}
        // 2. 把空对象和构造函数通过原型链进行链接
        newObj.__propto__ = Fun.prototype
        // 3. 把构造函数的this绑定到新的空对象上
        const result = Fun.apply(newObj, args)
        // 4. 根据构造函数返回的类型判断，如果是值类型，则返回对象，如果是引用类型，就要返回这个引用类型
        return result instanceof Object ? result : newObj
    }

js 的继承​

  • 原型链继承， 让一个构造函数的原型是另一个类型的实例， 那么这个构造函数 new 出来的实例就具有该实例的属性
  • 优点：写法方便简洁，容易理解
  • 缺点：对象实例共享所有继承的属性和方法，无法向父类构造函数传参
  • 借用构造函数继承，在子类型构造函数的内部调用父类型构造函数，使用 apply()或 call()方法将父对象的构造函数绑定在子对象上。
  • 优点：解决了原型链实现继承不能传参的问题和父类的原型共享的问题
  • 缺点：借用构造函数的缺点是方法都在构造函数中定义，因此无法实现函数复用。在父类型的原型中定义的方法，对子类而言也是不可见的，结果所有类型都只能使用构造函数模式
  • 组合继承，将原型链和借用构造函数组合到一块。使用原型链实现对原型属性和方法的继承，而通过借用构造函数来实现对实例属性的继承。这样，既通过在原型上定义方法实现了函数复用，又能够保证每个实例都有自己的属性
  • 优点：就是解决了原型链继承和借用构造函数造成的影响。
  • 缺点：无论在什么情况下，都会调用两次父类构造函数，一次是在创建子类原型的时候，另一次是在子类构造函数内部
  • ES6 class 实现继承， class 通过 extends 关键字实现继承，其实质是先创造出父类的 this 对象，然后用子类的构造函数修改 this。子类的构造方法中必须调用 super 方法，且只有在调用 super()之后才能使用 this，因为子类的 this 对象是继承父类的 this 对象，然后对齐进行加工，而 super 方法表示的是父类的构造函数，用来新建父类的 this 对象
  • 优点：语法简单易懂，操作更方便
  • 缺点：并不是所有的浏览器都支持 class 关键字

js 中关于 this 指向的问题​

  • 普通函数里面的 this 指向 window
  • 如果函数是对象中的一个属性，this 指向调用它的对象
  • 作为构造函数使用，this 指向创建的实例对象

script 标签里的 async 和 defer 有什么区别​

  • 无 async/defer：浏览器在解析 HTML 过程中遇到没有这两个属性的脚本时，会立即停止对 HTML 的解析，转而去下载并执行脚本，执行完成后才会继续解析 HTML。脚本会按照在 HTML 中出现的顺序依次下载并执行，前一个脚本执行完才会处理下一个。脚本执行时，可能 DOM 还没有完全解析完成，所以不能保证可以访问到完整的 DOM。
  • async：脚本的下载是异步进行的，不会阻塞 HTML 的解析。一旦脚本下载完成，浏览器会立即暂停 HTML 解析，执行脚本，执行完毕后再继续解析 HTML。各个脚本的下载和执行是相互独立的，因此它们的执行顺序可能和在 HTML 中出现的顺序不一致。脚本执行时，HTML 解析可能还未结束，同样不能保证可以访问到完整的 DOM。
  • defer：脚本同样是异步下载，不会阻塞 HTML 解析。不过，脚本会在 HTML 解析完成后、DOMContentLoaded 事件触发前按照在文档中出现的顺序执行。脚本会按照在 HTML 中出现的顺序执行，即使后面的脚本先下载完成，也会等待前面的脚本执行。脚本在 HTML 解析完成后执行，所以可以访问到完整的 DOM。

Promise​

  • 解决回调地狱的问题
  • 自身 有all，reject，resolve，race等方法
  • 原型上有then，catch
  • 把异步操作队列化
  • 三种状态：pending（初始状态），fulfilled（操作成功），rejected（操作失败）
  • 状态一旦改变就不会在变，不可逆
  • async await，同步代码做一步操作，两者必须搭配使用
  • async表明函数内有异步操作，调用函数会返回promise
  • await后面的内容如果是promise那么久返回promise的结果，如果是普通函数就链式调用
  • await后的promise如果是reject状态，那种这个async函数都会中断，后面的代码就不执行了。

call，apply，bind 三者有什么区别​

  • 都是改变 this 指向和函数的调用，call 和 apply 的功能类似，只是传参的方法不同
  • call 传递的是一个参数列表
  • apply 传递的事一个数组
  • bind 传参后不会立即执行，而是返回一个改变了 this 指向的函数，这个函数还是可以传参的，bind()()
  • call 的性能比 apply 好一些

什么是事件循环​

  • 主线程、执行栈、任务队列、宏任务、微任务
  • 主线程先执行同步任务，然后才去执行任务队列里面的任务，如果在执行宏任务之前有微任务，那么先执行微任务，全部执行完之后等待主线程的调用，调用完再去任务队列中查看是否有异步任务，这样一个循环往复的过程就是事件循环

ajax 是什么， 怎么实现​

  • 创建交互式网页应用的网页开发技术，在不重新加载整个网页的前提下，与服务器交换数据并更新部分内容
  • 通过 XmlHttpRequert 对象想服务器发送异步请求，然后从服务器拿到数据，最后通过 JS 操作 DOM 更新页面
  1. 创建 XmlHttpRequest 对象，xhr
  2. 通过 xhr 对象里的 open()方法与服务器建立连接
  3. 构建请求所需的数据，并通过 xhr 对象的 send()发送给服务器
  4. 通过 xhr 对象的 onreadystate changes 事件监听服务器和你的通信状态
  5. 接受并处理服务器响应的数据结果
  6. 把处理的数据更新到 html 页面上

get 和 post 有什么区别​

  • get 一般是获取数据，post 一般是提交数据
  • get 参数会放在 url 上，所以安全性较差，post 是放在 body 中
  • get 请求刷新服务器或退回是没有影响的，post 请求退回时会重新提交数据
  • get 请求会被缓存，post 请求不会被缓存
  • get 请求会被保存在浏览器历史记录中，post 不会
  • get 请求只能进行 url 编码，post 请求支持很多种

promise 的内部原理是什么？它的优缺点是什么？​

  • Promise 构造函数接收一个执行器函数 (resolve, reject) => {}，该函数会立即执。resolve 和 reject 是两个内置函数，用于改变 Promise 的状态。
  • then()：注册成功回调（状态变为 fulfilled 时触发）。
  • catch()：注册失败回调（状态变为 rejected 时触发）。
  • finally()：无论状态如何都会触发。
  • Promise 一旦创建就无法中途取消，即使操作不再需要

promise 和 async 和 await 的区别是什么​

  • 都是处理异步请求的方式
  • promise 是 ES6，async await 是 ES7
  • async await 是基于 promise 实现的，它和 primise 都是非阻塞性的
  • promise 的返回对象我们要用 then，catch 方法去处理和捕获异常，并且书写方式是链式，容易造成代码重叠，不好维护，async await 是通过 try catch 进行异常捕获
  • async await 最大的优点就是能让代码看起来像同步一样，只要遇到 await 就会立刻返回结果，然后在执行后面的操作

浏览器的存储方式有哪些​

  • cookies

    • h5 标准前的本地存储方式，兼容性好，请求头自带 cookie，存储量小

  • localstorage （同步的）

    • h5 加入的以键值对为标准的方式，操作方便，永久存储，兼容性较好，保存值的类型被限定，浏览器在隐私模式下不可读取，不能被爬虫

  • seesionstorage

    • 当前页面关闭后就会立刻清理，绘画级别的存储方式

  • indexedDB （异步的）

    • h5 标准的存储方式，以键值对进行存储，可以快速读取，适合 web 场景，IndexedDB 是浏览器端存储复杂数据的强大工具，适合需要大量结构化数据存储的应用场景。虽然 API 相对复杂，但提供了事务、索引等数据库级别的功能，是开发离线应用或高性能前端应用的重要选择。与 localStorage 相比，它支持事务操作、索引查询、二进制存储，并且没有存储上限（通常受限于硬盘空间）。

  • token -验证身份的令牌，一般就是用户通过账号密码登录后，服务端把这些凭证通过加密等一系列操作后得到的字符串

  • token 的登录流程

  • 客户端用账号密码请求登录

  • 服务端收到请求后，需要去验证账号密码

  • 验证成功之后，服务端会签发一个 token，把这个 token 发送给客户端

  • 客户端收到 token 后保存起来，可以放在 cookie 也可以是 localstorage

  • 客户端每次向服务端请求资源的时候，都需要携带这个 token

  • 服务端收到请求，接着去验证客户端里的 token，验证成功才会返回客户端请求的数据

  • 页面渲染的过程是怎样的

  • 用户输入网址，浏览器进行补全

  • 进行 dns 解析

  • 与服务器建立 tcp 连接

  • 发送 http 请求

  • 渲染页面

    1. 浏览器会获取 html 和 css 的资源，然后将 html 解析成 DOM 树，将 css 解析成 CSSOM 树
    2. 把 DOM 和 CSSOM 合并成渲染树
    3. 对元素进行布局计算，计算出元素的大小位置
    4. 将每个元素节点渲染到屏幕上

DOM 树和渲染树有什么区别​

  • DOM 树和 HTML 标签是一一对应的，包括 head 和隐藏元素
  • 渲染树不包含 head 和隐藏元素

雪碧图（精灵图）和 base64 的区别​

  • 雪碧图：把多张小图整合到一张大图上，利用定位的一些属性把小图显示在页面上，当访问页面可以减少请求，提高加载速度
  • base64：将原本的二进制数据转为字符串数据，base64 会和 html css 一起下载到浏览器中，减少请求，减少跨域问题，但是一些低版本不支持，base64 体积比原图大

svg 格式​

  • 基于 xml 语法格式的图像格式，可缩放矢量图，其他图像是基于像素的，SVG 是属于对图像形状的描述，本质是文本文件，体积小，并且不管放大多少倍都不会失真
  1. SVG 可直接插入页面中，成为 DOM 一部分，然后使用 JS 或 CSS 进行操作 --> <svg></svg>
  2. SVG 可作为文件被引入 --> <img src='pic.svg'>
  3. SVG 可以转为 base64 引入页面

了解过 JWT 吗​

  • JSON Web Token 通过 JSON 形式作为在 web 应用中的令牌，可以在各方之间安全的把信息作为 JSON 对象传输、授权 JWT 的认证流程：
    1. 前端把账号密码发送给后端的接口
    2. 后端核对账号密码成功后，把用户 id 等其他信息作为 JWT 负载，把它和头部分别进行 base64 编码拼接后签名，形成一个 JWT
    3. 前端每次请求时都会把 JWT 放在 http 请求头的 Authorization 字段中
    4. 后端检查是否存在，如果存在就验证 JWT 的有效性（签名是否正确，token 是否过期）
    5. 验证通过后后端使用 JWT 中包含的用户信息进行其他的操作，并返回对应结果 优点：简介、包含性，因为 Token 是 JSON 加密的形式保存在客户端，所以 JWT 是跨语言的，原则上任何 web 形式都支持。

http 协议规定的协议头和请求头有什么？​

  1. 请求头信息：

    • Accept：浏览器告诉服务器所支持的数据类型
    • Host：浏览器告诉服务器我想访问服务器的那台主机
    • referer： 浏览器告诉服务器我是从哪里来的（防盗链）
    • User-Agent：浏览器类型、版本
    • Date：浏览器告诉服务器我是什么时候访问的
    • X-Request-With：连接方式
    • Cookie

  2. 响应头信息：

    • Location：这个就是告诉浏览器你要去找谁
    • Server：告诉浏览器服务器的类型
    • Content-Type：告诉浏览器返回的数据类型
    • Refresh：控制定时刷新

浏览器的缓存策略​

  • 强缓存：不发起请求，直接使用缓存中的内容，浏览器把 JS，CSS，image 等存到内存中，下次用户访问直接从内存中取，提高性能
  • 协商缓存：需要想后台发请求，通过判断来决定是否使用协商缓存，如果请求内容没有变化，这返回 304，浏览器就用缓存里的内容
  • 强缓存的触发：
    • http1.0：时间戳响应表头
    • http1.1：Cache-Control 响应表头
  • 协商缓存的触发：
    • http1.0：请求头：if-modified-since，响应头：last-modified
    • http1.1：请求头：if-none-match，响应头：Etag

说一下什么是同源策略​

  • 同源策略是浏览器的核心，如果没有这个策略就会遭受网络攻击
  • 主要指的就是协议+域名+端口号三者一致，若其中一个不一样则不是同源，会产生跨域
  • 三个允许跨域加载资源的标签：img，link，script
  • 跨域是可以发送请求的，后端也会正常返回结果，只不过这个结果被浏览器拦截了
  1. JSONP 利用 script 标签
  2. CORS 后端实现了 cors，就能跨域，设置一下响应头 acesss-origin 什么什么的
  3. WebSocket
  4. 反向代理

防抖和节流是什么​

  • 都是应对页面中频繁出发事件的优化方案
  • 防抖：
    1. 延迟执行：在事件被触发后，延迟 n 毫秒再执行回调函数。
    2. 重置计时器：如果在延迟期间内再次触发事件，则重新计时。
    3. 仅执行最后一次：最终只执行最后一次触发的回调。
  • 使用场景：频繁和服务端交互，搜索框联想，用户输入时，等待输入完成后再触发搜索请求。窗口 resize：避免频繁计算布局，只在窗口调整结束后执行重绘。
  • 节流：
    1. 固定频率执行：在一定时间间隔内，只执行一次回调函数。
    2. 忽略中间触发：如果在间隔内多次触发事件，只有第一次有效。
    3. 时间窗口控制：通过记录上次执行时间或使用定时器实现。
  • 滚动加载：监听滚动事件，每隔一段时间加载更多内容。

大文件上传​

分片上传：

  1. 把需要上传的文件按照一定的规则，分割成相同大小的数据块
  2. 初始化一个分片上传任务，返回本次分片上传的唯一标识
  3. 按照一定的规则把各个数据块上传
  4. 发送完成后，服务端会判断数据上传的完整性，如果完整那么就会把数据合并成原始文件 断点续传： 服务端返回，从哪里开始，浏览器自己处理

webpack 是怎么打包的​

  • webpack 会把 js css image 看做一个模块，用 import/require 引入
  • 找到入口文件，通过入口文件找到关联的依赖文件，把它们打包到一起
  • 把 bundle 文件，拆分成多个小的文件，异步按需加载所需要的文件
  • 如果一个文件被多个文件引用，打包时只会生成一个文件
  • 如果引用的文件没有调用，不会打包，如果引入的变量和方法没有调用也不会打包
  • 对于多入口文件，加入引入了相同的代码，可以用插件把它抽离到公共文件中
